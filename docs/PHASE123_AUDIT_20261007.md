### PH123-001 — Deleted-account checkpoint blocks unrelated recovery

Severity: **HIGH**. Status: **OPEN**. Source: `migrations/000162_worker_recovery_checkpoints.up.sql:1`; `migrations/000060_worker_failure_observability.up.sql:1`; `internal/app/account_purge.go:91`; `internal/worker/recovery_checkpoint.go:130`.

Trigger: An abandoned recovery checkpoint remains when its account is purged. The checkpoint has no account FK; account purge omits it, while failure rows have an account FK.

Impact: Reaping the oldest orphan fails with SQLSTATE23503 before unrelated work is discovered. Repeated scans cannot repair it. A selective write failure has the same module-wide blast radius. Panels and the other recovery kind module are not directly stopped by this return.

Evidence: REAL_POSTGRES. Tests: `TestAuditDeletedAccountCheckpointPoisonsOtherAccounts`, `TestAuditPoisonedCheckpointBlocksUnrelatedAccount`. The FK sequence and actual reconciler were exercised in an isolated schema; the full account-purge API was reviewed, not invoked.

Correction direction: Coordinate account purge with live recovery ownership; safely reconcile removed-account checkpoints with explicit terminal evidence. Fence a poisoned item without silently admitting that same item or blocking healthy accounts.

Required fix acceptance: Purge while pending/live recovery exists; no orphan, no unsafe replay, healthy accounts progress. Inject selective checkpoint persistence errors and restart.

### PH123-003 — Capacity batch accounting can falsely restart the panels role

Severity: **HIGH**. Status: **OPEN**. Source: `cmd/worker/main.go:536`; `cmd/worker/main.go:596`; `cmd/worker/supervision.go:58`; `internal/supervision/registry.go:136`.

Trigger: Capacity fill starts a 30-second root work budget, then processes the entire fleet eight at a time. Runtime acquisition is before tracked WorkBudget admission. Multiple bounded slow/failing acquisition waves exceed the root deadline.

Impact: A progressing fleet batch can be labelled stalled and stop the entire panels role. Cleanup has the analogous 75-second batch versus 60-second per-panel acquisition mismatch.

Evidence: ACTUAL_REGISTRY_DETERMINISTIC_CLOCK. Tests: `TestAuditCapacityFillChargesWholePreAdmissionBatch`. Actual module policy and registry with a deterministic four-wave timing model prove deadline expiry; role exit/restart is the source-derived supervisory consequence, not a process restart exercised by this probe. Cleanup is source-derived only.

Correction direction: Track acquisition and semaphore waiting explicitly as per-item work and dispatcher progress; use finite batch contracts. Do not merely extend deadlines.

Required fix acceptance: 32 slow-but-bounded panel acquisitions across four waves keep role healthy; one genuinely stuck acquisition is bounded; unrelated modules continue.

### PH123-005 — Live async child masks scanner deadline

Severity: **MEDIUM**. Status: **OPEN**. Source: `internal/supervision/registry.go:219`; `internal/worker/worker.go:79`; `internal/worker/lifecycle.go:59`; `cmd/worker/supervision.go:84`.

### PH123-008 — UTF-8 error truncation breaks durable failure recording
