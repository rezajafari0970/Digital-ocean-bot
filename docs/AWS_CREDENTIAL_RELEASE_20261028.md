## نقص اصلاح‌شده و حدود نتیجه

فیلدهای ساختاریافتهٔ اعتبارنامه قبلاً فقط با رویداد input در مقدار مخفی فرم
همگام می‌شدند. پرشدن خودکار یا تغییر بدون این رویداد می‌توانست اعتبارنامهٔ قدیمی
را ارسال کند. اکنون اعتبارسنجی از فیلدهای نمایان می‌خواند؛ نتیجه به ارائه‌دهنده،
اعتبارنامه و پراکسی اصلی همان درخواست وابسته است. تغییر در زمان بارگیری،
دریافت پاسخ یا پیش از Save، اعتبارسنجی مجدد می‌خواهد. مسیرهای کلید خام،
AWS با session token و مجوزدهی OVH در آزمون‌ها حفظ شدند.

این نقص به‌صورت مستقل بازتولید شد، اما **علت قطعی رد اعتبارنامهٔ داخل تصویر
ثابت نشده است**. پاسخ واقعی AWS یک رد احراز هویت بود؛ اطلاعات واردشدهٔ آن
فرم ذخیره نشده‌اند. تغییر کد نمی‌تواند کلید حذف‌شده، منقضی، نادرست یا مجموعهٔ
نامنطبق را معتبر کند. برای پذیرش زندهٔ AWS باید پس از تازه‌سازی پنل، کلید و
secret متناظر و در صورت موقت‌بودن، session token همان مجموعه، فقط داخل
پنل وارد و دوباره Validate شوند. کلید نباید در گفتگو یا گزارش قرار گیرد.
تا موفقیت این مرحله، اتصال همان حساب را حل‌شده نمی‌نامیم.

بررسی خواندنی Kamatera در ۰۶:۰۵:۵۷ تهران، پنج سرور و پنج رکورد تاریخی صف را
برگرداند؛ هیچ‌کدام با سه نام قطعی intentها منطبق نبود. در پذیرش نهایی هر سه
تعداد ارسال **۱** و زمان dispatch قبلی را حفظ کردند. هیچ create تکراری،
آزادکردن reservation یا terminal جعلی اعمال نشد. نبودن در inventory اثبات
عدم ساخت نیست. اطلاعات شناسایی لازم در شواهد خصوصی عملیات نگهداری شده‌اند.

خطای پراکسی OVH در مشاهدهٔ بعدی توسط چرخهٔ عادی بهبود یافت؛ تغییری در
پراکسی یا سیاست خروج ترافیک اعمال نشد و پایداری دائمی آن ادعا نمی‌شود.
حساب DELETED نگهداری‌شده، حذف فعالِ ناتمام محسوب نشد؛ تعداد حذف فعالِ
ناتمام در بررسی تکمیلی صفر بود. تنظیمات حساب‌های DigitalOcean تغییر نکرد؛
محدودیت ارائه‌دهنده با حذف سرور یا نادیده‌گرفتن وضعیت حساب دور زده نشد.
