# Installer bootstrap recovery

Production diagnosis, 2026-10-06: the recovery handler unconditionally promoted any deployment at the provision step into WAITING_INSTALLER when its immutable plan contained a placeholder. A temporary failure or in-progress bootstrap was therefore skipped. Failed replacement deployments had no kernel-memory-guard events, despite containing that step in their plan. Pinned SSH inspection of two currently owned VMs confirmed kernel 7.0.0-38-generic, affected=true, prepared=false, no kho=off; one had already rebooted. Rebooting without preparing the workaround could not change readiness.

The shortcut is removed. Installer activation acquires the same deployment lease as provisioning, rereads state and requires durable successful SSH, readiness and all pre-placeholder steps. A premature WAITING_INSTALLER without any installer execution is transactionally repaired to its first unfinished prerequisite. Snapshot, attempts, retry deadlines and completed steps remain intact. Failed runs, retiring/deleted/ready resources, deleting accounts and stale versions cannot be repaired. Missing prerequisite evidence after an installer has begun fails closed rather than replaying bootstrap over installed services.

Provisioning now skips durable completed steps when resuming a checkpoint and propagates successful-finish persistence errors before advancing. This covers a lost checkpoint write and gaps in historically corrupted runs. Custom and legacy placeholder plans keep their own order and commands.

A historical accidental pre-guard reboot may be rearmed once, only after the missing guard is durably completed after the original schedule. The original schedule is retained in the marker/event. New reboot intents persist a boot ID before dispatch. Lost responses and worker crashes reconcile only that boot through a conditional SSH command; a later boot cannot be rebooted by the old intent. The existing three-minute budget is not extended on ordinary retries. Historical records without boot proof are not blindly replayed. Readiness still requires actual successful observations; no reboot-required marker is erased.

Tests: full Go suite; focused race suite; isolated PostgreSQL schemas with all migrations; 12-way competing repairs and one correction claim; transaction/event-write fault; preserved backoff, terminal state and attempts; completed-step replay prevention; failed finish write; original/changed boot shell execution with mocked systemctl; interrupted dispatch/lost SSH response without extending the budget; default/custom/legacy plans; existing KHO operator-state safeguards.

Source review: an initial NULL-history concern did not apply because migration113 defines last_error NOT NULL DEFAULT empty. Its claim-before-dispatch failure concern was resolved with persisted boot identity and bounded command reconciliation. Follow-up source review PASS. Live acceptance is recorded separately.

No schema, provider routing, account Desired/Lifetime/toggle, Xray, residential publication or guardian configuration change. Backup/atomic release/rollback: /root/backups/dob-installer-bootstrap-20261006. Binary rollback cannot undo already executed bootstrap or provider lifecycle work. Preserve journals, pins and additive schema; do not mass-reset states. Live acceptance must distinguish fixed installer ordering from unrelated fleet or provider health.
