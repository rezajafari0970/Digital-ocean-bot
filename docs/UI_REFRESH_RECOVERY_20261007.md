## Implemented behavior
A self-contained helper at the start of app.js owns each page view, aborts its obsolete GETs and bounds reads to15seconds including body parsing. Render results require current view identity; polls also require the original connected DOM nodes. Configs, Output automation and client operations use single-flight polls, retain last good data on network/HTTP/null/malformed/hung responses and retry with5..30second backoff. Initial page read failures also retry, with online/visibility wakeup. Modal edits are preserved. Empty eligible capacity snapshots show unavailable counts instead of inferred zero. Main page, dashboard, account detail and build-activity render paths use view fences; account preserveHash callbacks cannot invalidate another route. Logout invalidates reads; an old response cannot log out a replacement session. A read timeout never retries a mutation or reopens an execution gate.

The helper stays in app.js to avoid a new runtime dependency when an older cached HTML document loads the new script. HTML has a new cache-busting query. Existing saved policy, cleanup controls, ownership, finite budgets, auth, IPv4/routing and native Sanaei reads remain authoritative. No cloud fixture, raw gate mutation, credential change or runtime service restart is required for this static deployment.
