# Linode provider

Linode is registered through the same provider factory and runtime interfaces as DigitalOcean, Vultr and UpCloud. The existing account forms, encrypted credential storage, per-account network policy, scheduling, deployment keys, provisioning, lifecycle polling, replacement and account deletion paths remain authoritative.

## Supported contract

- API v4 with a bearer Personal Access Token, HTTPS and the application's supplied proxy/mutation-fencing transport. Redirects are rejected. Response bodies, tokens and SSH keys are not included in errors.
- Account identity uses the provider's external account UUID, not the local account name.
- Complete paginated inventory is required; missing/null lists, duplicate identities, changing totals and truncated pages fail closed.
- Core regions available to the account; supported CPU types with published plan/region availability; public nondeprecated Ubuntu 26.04, 24.04 and 22.04 images when actually available.
- Region-specific USD hourly prices and provider monthly caps. Hourly-only plans have no invented monthly cap. Prices exclude taxes and optional services.
- Inline SSH authorization installs the existing per-deployment root public key. No provider-global SSH key or root password is created.
- Creation uses local instance disks, public IPv4 and no external volumes, reserved IPs or private IP request. Linode may allocate IPv6; the existing guest/proxy IPv4 policy still governs traffic.
- Automatic account backups and Managed service can add charges. Creation is rejected if either is enabled; account-wide settings are never changed by this driver.
- Numeric instance IDs, explicit provisioning/ready/stopped/deleting states, public IPv4 readiness and existing bounded lifecycle polling.
- Ambiguous POST results are not automatically retried by the driver. The shared operation executor reconciles stable account/deployment ownership tags before considering a retry.
- Deletion rechecks provider identity and this account's ownership tags. HTTP 404 is idempotent success; access errors and locks are not absence. Local lifecycle completion still requires provider confirmation.
- The instance deletion endpoint removes its local disks and backups. Manually attached block volumes are detached and reserved IPs may survive; this driver does not create these resources and never sweeps unrelated account resources.
- Resource registry writes are scoped to account/provider and transactional. A resource is managed only with both a local live droplet and this account's provider tags.

## Credentials and capacity

The token/user must have account read access (including settings and regional service availability), Linode read/write access and permission to create/tag/delete instances. The profile must explicitly report unrestricted access. Restricted or missing access evidence is rejected before inventory, single-instance verification and mutations; a partial-access user cannot establish account-wide usage. Images must be readable. Linode itself enforces quotas and permissions.

The published OpenAPI contains compute quota path placeholders without a GET operation. Therefore the exact server maximum stays unknown. Current usage comes from complete instance inventory; observed usage is a lower bound, never an exact maximum or unlimited capacity. Explicit account-limit responses are classified as capacity failures and follow existing bounded workflow fallback/retry policy. No synthetic quota is stored.

Distributed sites, GPU/accelerator plans, private/custom images, external volume management and reserved IP management are outside this driver's supported deployment contract.

## Verification and release gates

Run `bash tools/linode-acceptance.sh -race` with a dedicated `BULK_TEST_DATABASE_URL` whose database name contains `bulk_test`. The script never points tests at production. Browser tests use an ephemeral local fixture with cloud mutations blocked.

Gates include all-provider race tests, Linode transport/pagination/error/ownership/catalog tests, isolated PostgreSQL integration, four-provider account lifecycle/rule parity, mutation fencing, browser create/edit/price/unknown-capacity behavior, and the repository's default test suite. Native/cloud opt-in tests in the default suite are reported separately; none constitute live Linode certification.

The review helper binds the OpenAI review receipt to the exact source digest that passed acceptance. API receipts retain actual input/output token usage. Billing cost is unknown unless an authoritative billed amount is supplied.

No real Linode account credential was provided during implementation. A live create → provision → ready → delete acceptance run remains pending that credential and an authorized account configuration; fixture results are not represented as live cloud evidence.
