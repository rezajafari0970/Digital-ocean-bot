# بررسی FinalMask برای خروجی کانفیگ Reality

## دامنه و نتیجه

کاربر روشن کرد که مقصد، کانفیگ گوشی در Output است. دامنهٔ فعال‌سازی فقط پنل `810ac959-2fb9-44a9-b5f1-f832cd7416c4` مربوط به `209.222.30.208` است؛ برای هر دو کلاس DIRECT و RESIDENTIAL. IP به‌تنهایی کلید تنظیم نیست و سرور جایگزین یا آینده این پروفایل را به ارث نمی‌برد.

انتخاب اجرایی: `layered-balanced-v1`، ترکیب محدود برش رکورد TLS و برش نخستین write اتصال TCP. این انتخاب یک نقطهٔ شروع قابل آزمایش است، نه اثبات سریع‌ترین یا مقاوم‌ترین تنظیم برای تمام اپراتورها. آزمایش از شبکهٔ سرور کنترل انجام شده؛ دسترسی به مسیر همراه اول/ایرانسل کاربر برای ارزیابی DPI وجود ندارد.

## تنظیم منتخب

داخل `outbounds[].streamSettings` کلاینت VLESS/Reality:

```json
{
  "finalmask": {
    "tcp": [
      {
        "type": "fragment",
        "settings": {
          "packets": "tlshello",
          "length": "100-200",
          "delay": "0",
          "maxSplit": "3-6"
        }
      },
      {
        "type": "fragment",
        "settings": {
          "packets": "1-1",
          "length": "100-200",
          "delay": "0-1",
          "maxSplit": "3-6"
        }
      }
    ]
  }
}
```

فیلدهای مفرد `length` و `delay` عمداً برای سازگاری انتخاب شده‌اند. سورس دقیق Xray 26.9.9 آنها را وقتی آرایهٔ جمع موجود نیست قبول می‌کند. هر چهار حالت Off، TLS، TCP و ترکیبی با `run -test` روی 26.3.27 و 26.9.9 قبول شدند. این تأیید، پشتیبانی همهٔ نسخه‌های قدیمی‌تر یا همهٔ اپلیکیشن‌های اندروید نیست.

لایهٔ اول درونی است. `tlshello` رکوردهای TLS را می‌شکند؛ تأخیر صفر می‌تواند آنها را در یک write جمع کند. لایهٔ دوم write نخست را قطعه‌بندی می‌کند. تعداد write الزاماً تعداد بسته‌های روی سیم نیست؛ TCP و سیستم‌عامل امکان تجمیع دارند. مقدار `3-6` محدودیت تعداد قطعات است؛ قطعهٔ باقی‌مانده ممکن است از ۲۰۰ بایت بزرگ‌تر باشد. محل SNI در ClientHelloهای مختلف ثابت نیست و این اعداد تضمین برش در محل SNI نمی‌دهند.

## چرا کانفیگ پیشنهادی اولیه عیناً فعال نشد؟

- `lengths: ["0","104","1"]` در حالت `tlshello` یک رکورد TLS خالی می‌سازد. گزارش رسمی و آزمایش محلی نشان دادند که پیاده‌سازی Go/Reality آن را نمی‌پذیرد.
- `maxSplit: "0"` به معنی بدون سقف است؛ با قطعات یک‌بایتی سربار زیادی ایجاد می‌شود.
- در آزمایش جداگانهٔ Xray 26.9.9، گذاشتن fragment روی **ورودی سرور Reality** هنگام اتصال panic داد: `fragmentConn ... missing method CloseWrite`. این وضعیت با حذف صفر هم برطرف نشد. ورودی سرور در محصول تغییر داده نشد.
- «کامل‌تر» به معنی انباشتن تمام ماسک‌ها نیست. header-custom/sudoku یا برخی ماسک‌های UDP ممکن است نیازمند هماهنگی دو طرف باشند. QUIC tuning، masquerade UDP و Brutal متعلق به همین مسیر RAW/TCP Reality نیستند و به آن اضافه نشدند.

## آزمایش اتصال واقعی

هستهٔ سرور هدف: **Xray 26.9.9**. کلاینت آزمایشی 26.9.9 به همان سرور و به یک کانفیگ واقعی از هر کلاس وصل شد. هیچ حساب یا سرور ابری ساخته نشد. مقصدهای آزمایش `www.cloudflare.com/cdn-cgi/trace` و `browserleaks.com/ip` بودند. BrowserLeaks طبق سیاست قبلی مسیر آزمایشی رزیدنتال است.

| پروفایل | DIRECT، دو مقصد | RESIDENTIAL، دو مقصد |
|---|---|---|
| بدون ماسک | 2/2، HTTP 200 | 2/2، HTTP 200 |
| tls-record-v1 | 2/2، HTTP 200 | 2/2، HTTP 200 |
| tcp-balanced-v1 | 2/2، HTTP 200 | 2/2، HTTP 200 |
| layered-balanced-v1 | 2/2، HTTP 200 | 2/2، HTTP 200 |

در نمونهٔ ترکیبی، زمان کل درخواست Cloudflare تقریباً ۹۱ میلی‌ثانیه برای DIRECT و ۸۳ میلی‌ثانیه برای RESIDENTIAL بود. BrowserLeaks حدود ۳۷۵ میلی‌ثانیه و ۳٫۲۱ ثانیه بود. یک نمونهٔ کوتاه مقایسهٔ آماری سرعت نیست؛ اختلاف مسیر رزیدنتال را نمی‌توان فقط به FinalMask نسبت داد. این آزمایش میزان مقاومت در برابر DPI ایران یا سرعت لود AdMob را نمی‌سنجد.

## پیاده‌سازی و برگشت

- لایهٔ تنظیم هنگام **خواندن خروجی** به URI اضافه می‌شود. UUID، SNI، public key، short ID، fingerprint، flow، انتخاب پورت و مسیر DIRECT/RESIDENTIAL حفظ می‌شوند.
- اسنپ‌شات‌های اصلی و زمان first_seen/visible_until تغییر نمی‌کنند. فیلتر انقضا، تازگی، سلامت رزیدنتال و مالکیت کلاس همچنان اعمال می‌شود.
- تغییر فقط برای UUID پنل منتخب ذخیره می‌شود. پیش‌فرض fleet یا آینده وجود ندارد.
- ورود مدیر، شمارهٔ revision، قفل تراکنشی، شناسهٔ عملیات و audit مانع تغییر هم‌زمانِ گم‌شده یا تکرار ناخواسته می‌شوند.
- URI ناسازگار در یک پنل باعث قطع خروجی تمام سرورها نمی‌شود؛ مورد خراب حذف و تعداد در هدر `X-Output-Omitted-Invalid` اعلام می‌شود.
- Output → Client FinalMask → انتخاب سرور → **Rollback selected server** خروجی اصلی را برمی‌گرداند. تنظیم خامِ دلخواه و بدون محدودیت پذیرفته نمی‌شود.
- کلاینت برای اعمال یا برگشت باید اشتراک را Refresh کند و دوباره وصل شود. تغییر پنل، کانفیگ قبلاً دانلودشدهٔ گوشی را خودکار پاک نمی‌کند.
- **Copy Xray JSON Link** آرایه‌ای از کانفیگ‌های کامل Xray می‌دهد. برنامه باید واردکردن subscription کانفیگ سفارشی JSON را پشتیبانی کند. این لینک عمومیِ دارای توکن، همان محرمانگی و تفکیک کلاس اشتراک قبلی را دارد.

## انتخاب بر اساس آزمایش کاربر

با همان گوشی و همان شبکه، حالت بدون ماسک و سه پروفایل را با اتصال‌های تازه مقایسه کنید: درصد موفقیت، زمان اتصال، لود چند صفحه و زمان لود تبلیغ. در صورت افزایش زمان یا افت پایداری، ابتدا `tcp-balanced-v1` و سپس Off را امتحان کنید. موفقیت روی یک اپراتور قابل تعمیم قطعی به اپراتور دیگر نیست. FinalMask مشکل DNS، پروکسی رزیدنتال خراب، مهلت ۱۵ثانیه‌ای اپ یا ناسازگاری WebView/JavaScript SDK را به‌تنهایی رفع نمی‌کند.
