# Controller kernel memory protection — 2026-10-23

Live investigation found a controller coverage gap: provisioning protects managed nodes from the susceptible KHO/CMA kernel behavior, but the controllers themselves did not run that guard. Primary kernel 7.0.0-38 and secondary 7.0.0-34 enable CONFIG_KEXEC_HANDOVER_ENABLE_DEFAULT, lack kho=off, and reported CmaTotal=0 with CmaFree>0. This proves the known susceptible configuration and observed memory accounting anomaly. It does not prove that KHO caused every PostgreSQL checksum error, bad Go cache entry, or kernel fault.

The shared provisioning Python guard is extracted verbatim into an embedded source asset. Its generated remote commands remain byte-for-byte identical.
