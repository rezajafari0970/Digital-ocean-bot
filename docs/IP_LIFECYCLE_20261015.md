## Proposed implementation
Extend existing provider registry with optional IP capabilities, inventory and mutation interfaces; preserve account-isolated HTTP client, proxy fail-close, credential generation and mutation fence. All reads bounded, complete pagination validated, partial results never prove absence. No new compute creation path.

In existing PostgreSQL schema add IP policy per account/family, observations with nullable quota, provider allocations, endpoints, jobs, history, approvals/proofs. Separate allocations (billable provider prefix/IP identity) from endpoints (address lifetime, attachment and published configurations). Store normalized inet/cidr. Primary/manual/discovered IPs never become owned merely by inventory discovery. Ownership requires our persisted mutation intent plus definitive correlated provider response. Conflict/unknown acquisition remains journaled and billable risk; never discard or release by IP-diff heuristics.

Policies default disabled and operational settings unset. Enabled requires explicit desired/per-batch/spacing range/concurrency/lifetime/history scope/history age/diversity CIDR/currency/cost ceiling. No paid defaults. Policy update alone does not authorize resource writes. Approval binds immutable exact account/server/resource/family/count/cost/network-impact plan digest, operation scope, expiry and maximum cost. Cross-family shared limits and account budget checked under account lock; reservations counted before external call. Account delete and native server expiry must wait for unresolved owned allocation/protected endpoint obligations or explicitly migrate/close them, never cascade away billing evidence.

One independent lane per account, persistent next-run with jitter within chosen bounds; concurrency bounded globally and per-account. Driver retries do not loop. Transactional claim with SKIP LOCKED, account lock and fencing token. Persist operation intent before external API, store accepted operation handle/response before advancing. A RUNNING job recovered after restart enters RECONCILE, not PENDING. Timeout/5xx/read loss after request are unknown; fresh provider read required. Absence alone cannot prove timed-out allocation never succeeded; no replay unless definitive failure or provider-supported idempotency. No worker resubmission of ambiguous create. Rate limit Retry-After respected; retry budgets/backoff persisted; exhausted operations BLOCKED with next action.

States: PLAN -> ALLOCATE -> ATTACH -> NETWORK -> VERIFY -> PUBLISH -> DRAIN -> DETACH -> RELEASE -> RELEASE_VERIFIED. Steps distinct journal operations. New replacement must pass provider attachment, guest/listener/firewall, actual protocol connection plus route isolation, and external user-network IPv6/fallback evidence before publication. TCP connect alone is insufficient. Health receipts bound to endpoint/server/panel/config revision, family, port, route class and time. Missing evidence withholds endpoint output. Output substitutions preserve UUID/Reality keys/SNI/query/route class and use net.JoinHostPort for IPv6; only endpoint matching the same account and server expands existing validated output. Persist min(client expiry, server expiry, endpoint visibility)-10sec. No change to global IPv4-only DNS/provider/residential policy.

Retirement requires verified replacement/migration AND all previously published lease obligations expired; infinite client lease blocks destructive retirement pending explicit migration. Expired target lifetime alone does not release a still-valid endpoint. If no spare quota, wait; maintenance window requires its own approval. Healthy active addresses are not deleted just for prefix similarity. Withdraw visibility before release, keep provider allocation until all child endpoint obligations clear. Shared/manual prefixes cannot be released. Rollback before release reuses verified old endpoint; after release no promise of same address, reacquisition requires new approval.

IPv6 uniqueness: normalize/unmap IPv4-mapped values; reject zones, malformed, unspecified, multicast and nonpublic endpoints. Exact active duplicates globally rejected; history scope GLOBAL/ACCOUNT and retention explicitly selected. Diversity CIDR must be justified per provider and parent prefix; reject overlapping active diversity prefixes, not only textual equality. A parent may survive with one selected endpoint. No /64 global default. Limited replacement acquisition attempts, no allocate-delete loops to seek new ranges.

## Revision after real design review (R1–R6)
The design review returned REVISE. These are requirements for subsequent write-capable stages, not claims that the foundation implements the complete lifecycle.
1. Capability evidence is keyed by account, credential generation, provider product, family, region and server; absence or stale evidence blocks ordinary allocation. A bounded discovery canary requires separate explicit authorization. Active prefix exclusion is separate from history retention.
2. Approval binds recurring retained/detached/unknown and replacement-overlap liabilities, quote currency/granularity/expiry and funded horizon. Unbounded client leases need ongoing funded authorization. Exhausted budget preserves existing service, blocks new spending and reports unavoidable liability. Cleanup authority is scoped independently from expired acquisition authority.
3. Publication leases must commit before a config response; output, renewals, drain and delete serialize through a common admission fence. Existing unbounded configs remain protected until an enforceable migration receipt exists.
4. Persist an immutable dispatch authorization before provider IO. A worker may pause after authorization and send late; takeover cannot issue a new allocation. After possible dispatch, an absent list entry alone is insufficient proof to retry. Late responses append immutable receipts; a fenced reconciler applies them. Test pause-before-send/takeover/late send/late response/process death.
5. Every native server/account deletion path must share the transactional obligation fence, including unknown operations and implicit prefix release. Preserve billing and cleanup credentials until terminal reconciliation. Disabled account cleanup requires its own narrow authority. Out-of-band loss is an incident, not successful migration.
6. Snapshot/version each guest/listener/firewall/route footprint; compare revision before restoration and recheck previous endpoints and both route classes. Rollback after guest changes is best effort; released addresses cannot be promised recoverable.
